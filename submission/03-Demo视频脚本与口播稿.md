# 速易通 Demo 视频脚本与口播稿

## 一、建议规格

- 主版本：4 分 30 秒至 5 分钟，1920×1080，30fps。
- 录制方式：屏幕录制 + 后期口播；鼠标移动放慢，关键按钮点击前停顿 0.5 秒。
- 浏览器：缩放 90%–100%，关闭书签栏、通知和个人账号头像。
- 录制前：模型与 Embedding 连通测试通过；准备一个已完成选题、文献和方法阶段的演示项目。
- 安全要求：环境配置页的 API Key 输入框保持空白；不打开 `.env`、终端环境变量或包含 Authorization 的网络面板。

## 二、主版本分镜与完整口播

### 00:00–00:20｜片头与一句话定位

**画面：** 标题动画后进入 `01-dashboard.png` 对应的工作台首页。  
**屏幕字幕：** 速易通｜基于 JiuwenSwarm 的可追溯科研 Agent 中台

**口播：**

> 大家好，这是速易通。它面向 Agent 方向科研短论文，把选题、文献、方法、实验和写作组织成一条可追溯、可审批、可复现的科研流程。我们希望解决的不是“让模型多写一点”，而是“让每一个结论都能回答从哪里来、如何验证、为什么可以写进论文”。

### 00:20–00:48｜科研写作的四个核心问题

**画面：** 简短文字动画：流程断裂、重复劳动、证据脱节、Agent 交接失忆。随后切回工作台流程图。

**口播：**

> 传统科研写作需要在检索、文档、代码和排版工具之间来回切换；普通大模型又容易把相似内容当成证据，多个 Agent 在交接时还会丢失决策原因和限制。结果是论文看起来完整，但引用、实验和结论之间并没有可靠的证据链。

### 00:48–01:15｜项目创建与状态机

**画面操作：** 点击“论文项目”，展示项目列表、手动输入研究方向和阶段状态。选中“面向长上下文任务的分层记忆检索方法”项目。

**口播：**

> 在速易通中，研究方向由用户手动输入，而不是从固定标签中选择。项目可以选择全流程或半流程模式。后台用结构化状态机保存阶段、产物和审批记录，所以聊天历史不是项目的唯一事实源，任务失败后也能定位到具体阶段。

### 01:15–01:43｜选题拆解

**画面：** 使用 `03-topic-framing.png`，依次放大需求澄清、候选题、研究问题和证据边界。

**口播：**

> 第一阶段由选题智能体拆解需求，生成候选题、研究问题、贡献假设和检索式。这里的关键不是生成更多标题，而是把每项主张关联到输入上下文，并把尚未完成文献验证的内容明确标成假设。用户确认后，流程才进入文献调研。

### 01:43–02:13｜真实文献调研

**画面：** 使用 `04-literature-review.png`；展示 OpenAlex/Crossref、去重数量、PAPER 编号、研究空白与检索限制。

**口播：**

> 文献阶段调用 OpenAlex 和 Crossref 获取真实学术元数据，按 DOI 与规范化标题去重，并为每条记录生成固定的 PAPER 编号。后续智能体只能引用白名单中的编号。摘要缺失、元数据冲突和检索覆盖不足都会保留，而不是由模型自行补全。

### 02:13–02:47｜PACM-SW 方法设计

**画面：** 使用 `05-method-design.png`；重点放大四层记忆、Provenance Contract 和检索公式。

**口播：**

> 速易通的核心方法叫 PACM-SW。它把项目上下文划分为约束、程序、情节和语义四层。检索时不仅计算语义和词法相关性，还考虑来源完整度、角色匹配、图关系、时效、冲突和冗余，再在固定 Token 预算内装配上下文。每个 Claim、Evidence、Experiment 和 Decision 之间都保留结构化关系。

### 02:47–03:18｜实验协议与真实检索

**画面操作：** 滚动到实验协议，展示 B0、B1、B2、B3、Ours、seeds 13/37/73；切换到真实检索结果和 JSONL Manifest。

**口播：**

> 实验模块会先冻结系统、任务、指标、预算和随机种子。我们已实现 B2 的 dense cosine、B3 的 BM25 加 dense RRF，以及 PACM-SW 的真实检索执行器。工程批次完成了九个配置、六条查询和三种子调度，共写入一百六十四条 JSONL，并用 SHA-256 封存。这里明确标记为工程验证，不作为论文效果结论。

### 03:18–03:53｜人工 qrels、消融与失败保留

**画面：** 使用 `08-formal-benchmark-demo.png`；展示人工标注入口、R1-R6、B0/B1 按钮和失败详情。

**口播：**

> 正式实验必须先完成人工 qrels。系统会合并各检索器候选并隐藏来源、排名和分数，由人工按零到三级标注。qrels 没有冻结时，正式检索和正式生成都会被 HTTP 409 阻断。R1 到 R6 分别移除溯源、时效、冲突、图连接、角色权重和溯源契约。模型连接失败或实验失败也会原样保留，不会被删除或补造。

### 03:53–04:18｜环境配置与 API 能力

**画面操作：** 切换“环境配置”，展示模型、Embedding、OpenAlex 配置状态，但不要点击或填写 Key；再切换“接口能力”。

**口播：**

> 平台采用第三方 API 路线，不要求本地 GPU。用户可以独立配置生成模型、Embedding 和 OpenAlex。密钥只保存在本机运行目录，查询接口只返回是否已配置。模型、检索源和向量服务都通过适配层替换，当前功能也完整暴露为 API，方便接入其他前端或评测平台。

### 04:18–04:40｜收束与路线图

**画面：** 返回工作台，叠加下一步三项：人工 Gold、正式矩阵、ICLR 交付。

**口播：**

> 目前速易通已经贯通从选题到实验的核心垂直链路。下一步将完成独立人工 Gold、五系统与六消融的正式评测，再输出 ICLR 风格论文、BibTeX、证据账本和复现清单。速易通的目标不是替研究者承担责任，而是让科研 Agent 的每一步都值得被检查。谢谢。

## 三、90 秒精简版口播

> 速易通是基于 JiuwenSwarm 的可追溯科研 Agent 中台，面向 Agent 方向科研短论文的全流程和半流程自动化。传统大模型能生成文字，却难以保证文献、实验、论点和多智能体决策之间始终一致。速易通用项目状态机串联选题、文献、方法、实验和写作，并在关键节点保留人工审批。文献阶段通过 OpenAlex 和 Crossref 获取真实元数据，所有引用必须来自 PAPER 白名单。核心方法 PACM-SW 把上下文组织为约束、程序、情节和语义四层，在语义相关性之外加入溯源、角色、图关系、时效、冲突和冗余评分。当前原型已实现 B2、B3 和 PACM-SW 真实检索、R1 到 R6 消融、三随机种子调度、盲化人工 qrels 及 B0/B1 生成框架。每次运行写入 JSONL 并通过 SHA-256 封存；人工 qrels 未冻结或模型调用失败时，正式质量门会直接阻断，不生成虚假的论文结论。我们的目标不是一键代写，而是让 Agent 产出的科研过程可检查、可回放、可复现。

## 四、录制前必做检查

1. 新建专用演示浏览器窗口，关闭微信、邮件和系统通知。
2. 点击“测试模型连接”和“测试 Embedding”；失败时不要录制完整生成环节。
3. 只展示密钥“已配置”状态，不展示真实值、请求 Header 或终端日志。
4. 预先打开项目页，避免录制中等待第三方 API。
5. 对较长产物采用局部放大和缓慢滚动；重要数字停留至少 2 秒。
6. 保留“ENGINEERING”“NO EFFICACY CLAIM”“QUALITY GATE BLOCKED”等真实性标签。
7. 视频结尾检查 GitHub 地址、项目名称和比赛赛题拼写。
