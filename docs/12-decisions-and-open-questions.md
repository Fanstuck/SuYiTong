## 2. 高优先级待确认事项

### OQ-001 比赛正式规则

- 截止日期是什么？
- 强制使用哪个 JiuwenSwarm/openJiuwen 版本？
- Short Paper 页数和语言要求是什么？
- 是否必须实际运行实验？
- 是否要求演示视频、代码仓库或部署包？
- 评分是产品、技术创新、论文还是综合？

影响：产品范围、论文模板、排期和验收。优先级：最高。

### OQ-002 主研究方向

是否正式选择 PACM-SW 可溯源上下文记忆，还是分别研究上下文工程、记忆、自演进后再决定？

影响：任务集、数据模型、实验和论文结构。优先级：最高。

### OQ-003 可用模型

- 可使用哪些国内/国外模型？
- 是否有华为云 MaaS 或其他比赛资源？
- API 预算和并发限制？
- 已确认不使用本地模型；仍需确定首选与备用 API 模型。

影响：Agent 设计、成本、公平性和复现。优先级：高。

### OQ-004 本地运行资源

- CPU、内存和磁盘空间；不再要求 GPU 或显存；
- Docker/WSL/容器环境是否可用；
- 是否有远程算力；
- 单次实验可接受时长。

影响：方法复杂度和任务集规模。优先级：高。

### OQ-005 用户与演示方式

首个可用版本主要面向：比赛评委、项目团队、学生研究者还是学者？是否需要多人协同？

影响：界面、权限和演示脚本。优先级：中高。

## 3. 技术验证后决定

- JiuwenSwarm v0.2.2 的准确标签与依赖；
- Swarmflow、人机审批、记忆和自演进在 v0.2.2 的可用程度；
- 是否需要修改 JiuwenSwarm 核心；
- SQLite 是否足以支持首个纵向切片；
- PostgreSQL/pgvector 何时引入；
- 实验执行使用 Docker、WSL 还是其他沙箱；
- 本地 Web 是否复用 JiuwenSwarm UI 或独立构建；
- 文献全文解析采用何种工具和许可策略。

## 4. 研究验证后决定

- PACM-SW 方法名称和正式定义；
- 任务集来源与规模；
- 主指标、统计检验和最小重复次数；
- 上下文排序公式和权重；
- 是否引入图数据库；
- 是否将自演进纳入论文实验；
- 是否需要人类受试者研究及伦理审批。
