# 02 比赛研究方向与论文选题

## 1. 目标

从 Agent 上下文工程、Agent 记忆引擎和 Agent 自演进三个建议方向中，选择一个能够被实现、被实验、被对照和被审稿的主要科研贡献。

## 2. 三个方向比较

| 维度 | 上下文工程 | 记忆引擎 | 自演进 |
|---|---:|---:|---:|
| 与科研写作的直接相关性 | 高 | 很高 | 中高 |
| 首期实现难度 | 中 | 中高 | 高 |
| 对照实验清晰度 | 高 | 高 | 中 |
| 数据与算力成本 | 中低 | 中 | 高 |
| 可解释性 | 高 | 高 | 中 |
| 风险 | 上下文策略可能缺少新意 | 容易退化为普通 RAG | 容易把检索经验误称为学习 |
| 比赛展示效果 | 高 | 高 | 很高 |
| 适合作为首篇主贡献 | 是 | 是 | 谨慎 |

## 3. 推荐主方向

推荐将“可溯源上下文记忆”作为主方向，把上下文工程和记忆引擎结合起来，自演进作为平台扩展能力而非首篇论文的主要结论。

推荐论文工作名：

> **Provenance-Aware Context Memory for Multi-Agent Scientific Writing**  
> 面向多智能体科研写作的可溯源上下文记忆方法

暂定方法名：**PACM-SW**（Provenance-Aware Context Memory for Scientific Writing）。方法名尚未冻结，需在完成相关工作检索后检查重名和新颖性。

## 4. 问题定义

多智能体科研写作面临三个相互关联的问题：

1. 文献、实验、讨论和写作产生大量异构上下文，无法全部放入模型窗口。
2. 普通向量检索只返回语义相似片段，不能保证论点与证据的来源和支撑关系。
3. 多个 Agent 在交接时容易丢失决策原因、误用过时证据或将推断写成事实。

PACM-SW 的目标是在有限上下文预算下，根据当前角色和任务，从项目记忆中选择最相关、最可信、最具溯源信息的内容，同时维持 Claim、Evidence、Experiment 和 Decision 之间的结构化关系。

## 5. 研究问题

- **RQ1**：结构化、可溯源的上下文记忆是否能降低虚假引用和无证据论点？
- **RQ2**：任务与角色感知的上下文选择是否能在更低 Token 成本下保持或提升论文质量？
- **RQ3**：显式 Claim-Evidence-Experiment 关系是否能改善多 Agent 阶段交接的一致性？
- **RQ4**：不同记忆组成部分中，溯源评分、图关系检索、时间衰减和冲突检测分别贡献多少？

## 6. 可证伪假设

- **H1**：PACM-SW 相比扁平向量 RAG，显著降低虚假参考文献率。
- **H2**：在相同或更小的上下文 Token 预算下，PACM-SW 提高 Claim-Evidence 支持率。
- **H3**：PACM-SW 提高跨阶段关键决策保持率，减少写作内容与实验结果不一致。
- **H4**：移除溯源或图关系约束后，性能下降，证明提升不只来自检索更多文本。

若实验不能支持上述假设，应如实缩小或否定贡献，不得通过重新定义指标规避失败。

## 7. 方法草案

### 7.1 记忆对象

- Research Goal：研究目标与约束；
- Decision：选择与放弃方案的原因；
- Evidence：文献证据及来源；
- Claim：论文论点及支撑关系；
- Experiment：实验计划、运行和结果；
- Limitation：结论限制、失败与不确定性；
- Draft Artifact：章节、表格、图和审稿意见。

### 7.2 检索与排序

候选记忆首先通过关键词、向量和图邻接检索召回，再使用组合分数排序：

```text
score = semantic_relevance
      + lexical_relevance
      + provenance_confidence
      + task_role_relevance
      + graph_connectivity
      + freshness
      - conflict_penalty
      - redundancy_penalty
```

具体权重必须通过开发集确定，并在测试集固定，禁止在最终结果上调参。

### 7.3 上下文装配

上下文按照固定区块装配：

1. 当前任务与输出契约；
2. 已批准研究决策；
3. 与当前任务关联的 Evidence/Claim/Experiment；
4. 已知冲突、限制和禁止事项；
5. 输出格式与质量规则。

## 8. 对照系统

- **B0 Single-Agent**：单 Agent，仅使用会话上下文。
- **B1 Multi-Agent Chat**：多 Agent，共享聊天记录，无外部记忆。
- **B2 Flat RAG**：多 Agent，使用普通向量检索。
- **B3 Hybrid Retrieval**：向量 + BM25，无结构化溯源关系。
- **Ours PACM-SW**：混合检索 + 图关系 + 溯源 + 角色感知预算。

## 9. 消融实验

- 去除 provenance confidence；
- 去除 Claim-Evidence 图关系；
- 去除角色感知；
- 去除冲突检测；
- 去除时间与版本信息；
- 固定 Top-K 与预算化动态选择对比；
- 团队记忆与仅项目全局记忆对比。

## 10. 自演进的定位

自演进首期只研究工程闭环：

```text
失败/纠正/质量门问题
  → 候选演进信号
  → 归因到 Skill/Prompt/Tool/Workflow
  → 生成候选修改
  → 固定回放集比较
  → 人工审批
  → 发布或拒绝
```

只有在积累足够多跨任务数据后，才考虑把自演进写成独立论文贡献。

## 11. 论文内容边界

论文应主张一个经过实验验证的方法，不应同时声称：

- 解决了所有学术写作问题；
- 实现了真正自主科学发现；
- 具备通用长期学习能力；
- 自动审稿分数等同于真实会议录用概率；
- 多 Agent 数量越多效果越好。

## 12. 方向冻结条件

只有满足以下条件后才冻结主方向：

1. 完成系统性相关工作检索并确认没有明显同名或重复方法。
2. 至少找到一个可公开复现的任务集或构建合规评测集的方法。
3. 证明核心方法可在现有算力预算内运行。
4. 明确自动指标与人工评审方案。
5. 完成一次小规模技术验证，显示方法存在可测差异。
