# 08 实验与评测方案

## 1. 评测目标

评测需要分别回答两个问题：

1. **研究方法是否有效**：PACM-SW 是否改善上下文效率、证据忠实度和跨 Agent 一致性？
2. **产品链路是否可靠**：速易通能否稳定生成可追溯、可复现、符合质量门的研究交付包？

不能只用论文外观、单次案例或自动审稿总分回答上述问题。

## 2. 评测对象

### 2.1 方法级评测

固定科研任务，比较不同 Agent/记忆配置下的中间产物和论文结果。

### 2.2 系统级评测

验证状态机、恢复、权限、产物版本、实验隔离、质量门和交付完整性。

### 2.3 用户级评测

评估人工审批负担、问题可理解性、证据浏览效率和修订可控性。

## 3. 任务集设计

任务应围绕 Agent 上下文、记忆和自演进，确保文献主要可从公开 AI 研究源获得。

建议分三阶段：

| 阶段 | 数量建议 | 用途 |
|---|---:|---|
| 技术验证集 | 3—5 | 验证数据模型、工具和指标可运行 |
| 开发集 | 10—15 | 选择检索权重、Prompt 和上下文预算 |
| 冻结测试集 | 15—30 | 最终对照和统计，不用于调参 |

最终数量根据算力与比赛时间调整。任务选择应覆盖：

- 文献密集与实验密集任务；
- 相近术语但不同研究问题；
- 存在冲突证据的任务；
- 长上下文与短上下文任务；
- 需要跨阶段保持关键决策的任务。

## 4. 对照配置

| ID | 系统 | 说明 |
|---|---|---|
| B0 | Single-Agent | 单 Agent，仅会话上下文 |
| B1 | Multi-Agent Chat | 多 Agent，共享对话，无外部检索记忆 |
| B2 | Vector RAG | 多 Agent + 扁平向量检索 |
| B3 | Hybrid RAG | 多 Agent + BM25/向量混合检索 |
| Ours | PACM-SW | 混合检索 + 研究图 + 溯源 + 角色感知预算 |

公平性要求：

- 使用相同基础模型或明确报告模型差异；
- 相同任务、工具和可访问文献集合；
- 控制总 Token/调用预算，或同时报告质量—成本曲线；
- 使用相同写作模板和质量门；
- 每个配置采用相同随机种子集合和重复次数。

## 5. 核心指标

### 5.1 文献真实性

```text
Reference Validity = verified references / all references
Fabricated Reference Rate = nonexistent or materially incorrect references / all references
```

验证范围至少包括标题、作者、年份和 DOI/arXiv ID。

### 5.2 Claim-Evidence 支持

```text
Claim Support Rate = supported core claims / all core claims
Numeric Traceability = numeric claims linked to exact metric / all numeric claims
```

“得到关联”不等于“得到支持”，需要检查证据是否确实蕴含或合理支撑 Claim。

### 5.3 跨阶段一致性

构建一组必须保持的关键事实和决策，检查进入写作阶段后是否：

- 被正确保留；
- 被错误修改；
- 被遗漏；
- 被过期版本覆盖。

```text
Decision Retention = correctly preserved decisions / required decisions
Experiment-Paper Consistency = matching reported results / checked reported results
```

### 5.4 上下文效率

- 总输入 Token；
- 每阶段输入 Token；
- 被使用的 Context Pack 比例；
- 单个有效 Claim 的 Token 成本；
- 端到端时长和模型费用。

应绘制质量—Token 和质量—成本曲线，而不是只报告一个预算点。

### 5.5 科研质量

- 研究问题重要性；
- 新颖性；
- 方法合理性；
- 实验充分性；
- 结论支持度；
- 写作清晰度；
- 相关工作定位；
- 可复现性。

评分必须同时保留维度分和文字证据。

### 5.6 系统可靠性

- 阶段成功率；
- 从检查点恢复成功率；
- 工具超时和错误处理率；
- 质量门误报/漏报；
- 产物 schema 通过率；
- 交付 manifest 验证率；
- 未授权工具调用拦截率。

## 6. 自动、外部与人工评测

### 6.1 确定性自动评测

用于文献标识、数值追溯、格式、页数、哈希、日志和复现。

### 6.2 内部 Agentic Review

使用固定审稿模板和不同审稿视角，输出维度评分、问题位置和置信度。内部 Reviewer 不访问系统标签，尽量避免知道哪个配置是 Ours。

### 6.3 Stanford Agentic Reviewer

作为外部 manuscript-only 评测：

- 仅在冻结测试版本上使用；
- 记录提交版本、时间和 venue；
- 保存分维度意见和文字反馈；
- 不把其总分作为唯一主指标；
- 首期人工上传，不依赖未公开 API 或网页自动化。

### 6.4 人工盲评

至少抽取一部分任务，由具备 Agent/ML 研究背景的评审者在不知道系统配置的情况下评分。

建议记录：

- 评审背景；
- 每篇评审时长；
- 维度评分；
- 关键问题；
- 评审者间一致性。

## 7. 消融实验

- Ours 去除 provenance；
- 去除 Claim-Evidence 图关系；
- 去除角色感知；
- 去除冲突检测；
- 去除版本/时间过滤；
- 固定 Top-K 替代预算化选择；
- 只用全局项目记忆，不使用团队记忆；
- 不进行上下文压缩。

每个消融只改变一个主要因素，其他条件保持一致。

## 8. 鲁棒性测试

- 文献元数据不完整；
- 两篇同名或近似标题文献；
- 撤稿或更正文献；
- Evidence 相互冲突；
- 工具超时或 API 限流；
- 一个 Agent 给出错误中间结论；
- 实验部分失败；
- 上下文预算骤减；
- 项目中途更换模型；
- 旧论文版本被错误召回。

## 9. 统计方案

- 在看冻结测试结果前确定主指标和检验方法；
- 对同一任务不同系统使用配对比较；
- 报告效应量和置信区间，不只报告 p 值；
- 多重比较时使用适当校正；
- 报告随机种子、重复次数和任务级分布；
- 自动审稿分数为有噪声测量，应结合人工与确定性指标解释。

具体统计检验需在任务集和指标分布确定后冻结。

## 10. MVP 工程验收阈值

以下是工程基线，不是论文预设结果：

- 已验证引用率：100%；
- 虚假引用率：0%；
- 核心 Claim 支撑关系完整率：100%；
- 论文数字可追溯率：100%；
- 成功实验运行的环境与日志记录率：100%；
- 匿名化阻断项：0；
- 交付 manifest 哈希通过率：100%；
- 质量门阻断项：0；
- 检查点恢复：关键阶段至少完成一次成功演练。

科研质量指标不应预设必须达到某个有利结果；若 Ours 未优于基线，应如实报告。
