# 11 风险、合规与治理

## 1. 风险原则

速易通服务于科研写作，系统错误可能形成虚假文献、错误结论、不可复现实验或版权与隐私问题。因此风险治理属于核心产品能力，不是交付前附加检查。

## 2. 主要风险清单

| ID | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| R-001 | 虚假或错误参考文献 | 学术完整性失败 | DOI/arXiv/标题验证；未验证条目禁止引用 |
| R-002 | Claim 与证据不匹配 | 结论失真 | Claim Ledger、证据位置、独立 Reviewer |
| R-003 | 伪造或补全实验结果 | 严重研究违规 | 结果只从 metrics 读取；失败运行不可删除 |
| R-004 | 数据泄漏或测试集调参 | 实验无效 | 冻结划分、运行 manifest、质量门 |
| R-005 | 多 Agent 互相放大错误 | 系统性幻觉 | 结构化交接、冲突记录、确定性验证 |
| R-006 | 错误记忆长期污染 | 跨任务持续失败 | 权威数据分层、状态/版本过滤、可删除候选记忆 |
| R-007 | 自演进破坏生产 Skill | 大面积回归 | 默认审批、回放测试、版本与回滚 |
| R-008 | JiuwenSwarm 版本漂移 | 无法复现或升级 | 固定 v0.2.2、适配器、最小 Fork |
| R-009 | 外部 API 限流/变化 | 文献和评测中断 | 缓存、退避、替代源、依赖监控 |
| R-010 | 未授权全文使用 | 版权风险 | 许可检查、只存授权副本、交付清理 |
| R-011 | 草稿或身份泄露 | 隐私/双盲失败 | 项目隔离、匿名化扫描、外发审批 |
| R-012 | 工具执行越权 | 数据或环境损坏 | allow/ask/deny、沙箱、目录白名单 |
| R-013 | 成本失控 | 项目无法完成 | 预算、阶段上限、缓存、高成本审批 |
| R-014 | 过度依赖自动审稿分数 | 研究目标偏移 | 多维指标、人工盲评、冻结测试 |
| R-015 | 范围过大 | 比赛前无法闭环 | 首期聚焦 Agent Short Paper，后续再扩学科 |
| R-016 | 端到端任务卡死 | 无法演示 | 超时、取消、检查点和降级路径 |

## 3. 学术完整性

必须禁止：

- 编造文献、DOI、作者、页码或引文；
- 编造数据集、基线、实验或统计结果；
- 选择性隐藏不利结果；
- 把模型观点包装为文献共识；
- 通过修改模板规避页数；
- 未经确认将系统列为作者或自动处理作者责任；
- 未按目标规则披露重大 LLM 使用。

每个交付包应包含机器生成内容的使用说明和人工批准记录。

## 4. 版权与文献访问

- 元数据优先使用公开、合规 API。
- 只下载开放获取或用户有权访问的全文。
- 不绕过登录、付费墙、验证码或网站限制。
- Evidence Ledger 保存必要定位和结构化总结，避免无必要复制全文。
- 交付包默认不包含第三方论文全文。
- 对外发布前检查图、表、数据和代码许可证。

## 5. 隐私与双盲

- 项目创建时标记是否需要匿名化。
- 匿名稿检查作者、机构、邮箱、致谢、仓库 URL、文件名、PDF 元数据和自引措辞。
- API Key 和个人信息不得进入 Prompt、日志或长期记忆。
- 外部模型调用前对输入进行数据分级和必要脱敏。
- 用户上传的未公开研究内容默认不用于跨项目 Skill 演进。

## 6. 工具与实验安全

实验容器默认：

- 非特权用户；
- 只读源数据；
- 限制写入目录；
- 限制 CPU/内存/磁盘/时间；
- 网络关闭或白名单；
- 禁止访问宿主凭据；
- 超时可终止；
- 保存退出码和错误。

任何扩大权限的操作都必须记录批准人、原因、范围和有效期。

## 7. 自演进治理

演进对象分级：

| 对象 | 风险 | 发布要求 |
|---|---|---|
| 示例/故障提示 | 低 | 自动测试后可简化审批 |
| Prompt 指令 | 中 | 回放对比 + 人工审批 |
| Skill 工作流 | 高 | 全量回归 + 版本发布 |
| 工具代码/权限 | 很高 | 代码审查、安全测试、人工发布 |
| 质量门规则 | 很高 | 规则评审、历史样本回放、变更记录 |

同一次任务产生的反馈不能同时作为演进训练信号和最终评测依据。

## 8. 模型治理

模型注册信息至少包含：

- 供应商、模型名和版本；
- API Base 和兼容协议；
- 工具调用和结构化输出能力；
- 上下文长度；
- 推理参数；
- 数据处理和保留政策；
- 成本与限流；
- 允许的项目数据等级。

更换模型会使部分评测结果失去可比性，必须生成新的系统配置版本。

## 9. 变更治理

重大变更包括：

- 主要研究问题或贡献变化；
- 数据集或测试划分变化；
- 主指标变化；
- 基础模型变化；
- JiuwenSwarm 基线版本变化；
- 质量门阻断规则变化；
- 权限或外部发布范围变化。

重大变更需要新增决策记录、说明原因和影响，必要时重新执行历史回放。

## 10. 外部自动审稿治理

- 只上传经人工批准的匿名稿；
- 上传前确认文件不含敏感信息；
- 保存提交版本哈希；
- 明确自动审稿可能有错误；
- 审稿反馈进入 ReviewIssue，不直接改写实验事实；
- 不依赖未公开 API，也不通过网页抓取绕过平台交互；
- 不以反复提交选最高分作为主要评测策略。

## 11. 事故处理

出现虚假引用、数据泄漏、越权工具调用、错误外发或实验污染时：

1. 立即暂停相关项目和自动执行；
2. 保全日志、事件和产物版本；
3. 确定影响的 Claim、论文和交付包；
4. 撤销或标记受影响产物；
5. 修复根因并运行回放；
6. 由人工批准恢复；
7. 必要时更新风险、质量门和 Skill。
