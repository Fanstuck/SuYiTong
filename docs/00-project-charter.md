# 00 项目章程

## 1. 文档信息

- 项目：速易通（SuYiTong）
- 版本：v0.1
- 日期：2026-08-14
- 状态：草案
- 当前阶段：产品与技术路线研究

## 2. 项目背景

现有速易通方案主要解决学术写作中的流程断裂、机械重复和质量判断问题，已经形成术语统一、结构诊断、引用检查、格式处理与人工确认等思路，并积累了专著重构、论文提炼、政策报告转化等场景材料。

比赛目标进一步要求围绕 Agent 关键技术，实现科研短论文的全流程或半流程自动化，覆盖选题、文献、方法、写作和结果分析，并以 ICLR 风格论文接受自动化审稿评价。因此，项目需要从“稿件加工工具”升级为“可追溯、可实验、可评测的科研智能体中台”。

## 3. 项目愿景

让研究人员能够把一个尚不完整的研究意图，逐步转化为有文献依据、有可复现实验、有明确结论边界、符合学术规范的科研短论文，同时保留人类对关键研究决策的控制权。

## 4. 产品定位

速易通不是通用聊天机器人，也不是一键代写工具，而是：

> 基于 JiuwenSwarm 的可追溯自动科研中台，通过多智能体协作、结构化研究状态、证据与实验账本、确定性质量门，支持 Agent 方向科研短论文的人机协同生成与评测。

## 5. 项目目标

### 5.1 产品目标

- 支持从研究主题或已有草稿进入科研流程。
- 支持全流程和半流程两种工作方式。
- 将文献、论点、实验、结论和论文段落建立可追溯关系。
- 支持人在选题、方法、实验成本、核心结论和最终交付处审批。
- 输出可继续编辑和复现的完整研究交付包。

### 5.2 研究目标

- 聚焦 Agent 上下文工程、Agent 记忆引擎或 Agent 自演进中的一个主要问题。
- 形成可证伪的研究问题、清晰的基线和消融实验。
- 证明所提方法相较单 Agent、普通多 Agent 或扁平 RAG 的改善。
- 将平台本身作为研究系统和实验载体，而不是只做展示界面。

### 5.3 工程目标

- 以 JiuwenSwarm v0.2.2 为可复现基线。
- 业务能力尽量通过独立后端、Skills 和工具服务扩展，减少核心 Fork。
- 所有运行能够记录模型、Prompt、Skill、工具、数据和代码版本。
- 关键质量规则能够自动执行并输出机器可读报告。

## 6. 非目标

当前阶段明确不做：

- HarmonyOS、移动端和端侧 NPU 推理。
- 自动替用户投稿、自动处理作者身份或自动签署声明。
- 无审批的高成本实验执行。
- 绕过版权、付费墙或访问权限抓取论文全文。
- 将 Stanford Agentic Reviewer 的分数作为唯一优化目标。
- 通过伪造文献、实验或统计显著性提升论文表面质量。

## 7. 核心原则

### 7.1 证据优先

任何重要事实或研究结论必须指向文献证据或实验产物。无法验证的内容只能标为假设、建议或待验证事项。

### 7.2 状态优先于对话

项目进度和研究结论由结构化状态与产物决定，聊天记录不是系统事实源。

### 7.3 确定性优先

能通过程序稳定完成的任务，例如 DOI 验证、引用编号、统计计算、模板编译、文件哈希和格式检查，不交给大模型自由判断。

### 7.4 人类保留研究责任

选题、研究伦理、实验风险、核心结论、作者身份与最终提交必须保留人工确认。

### 7.5 可回放与可审计

每次运行都要能回答：使用了什么模型、哪个 Prompt/Skill 版本、哪些数据和工具、产生了什么中间结果、为什么得出最终结论。

### 7.6 评测驱动演进

Prompt、Skill 或工作流只有在固定回放集上通过评测后才能进入新版本，不能因一次失败或一次用户纠正直接污染生产能力。

## 8. 成功定义

第一阶段成功不是“生成一篇看起来像论文的 PDF”，而是系统能够稳定输出：

- ICLR 风格英文论文 PDF；
- 可编辑 LaTeX 源文件；
- 经过验证的 BibTeX；
- Claim-Evidence Ledger；
- 实验计划、代码、环境与运行日志；
- 结构化结果和图表数据；
- 自动质量门报告；
- 人工审批记录；
- 可供外部审稿平台评测的匿名版 PDF。

## 9. 关键术语

| 术语 | 定义 |
|---|---|
| 研究项目 | 从研究问题到论文交付的一次完整工作单元 |
| 研究状态机 | 约束项目阶段、准入条件和回退路径的确定性流程 |
| Evidence Ledger | 保存文献和证据片段来源、位置、标识与用途的账本 |
| Claim Ledger | 保存论文核心论点及其支撑证据、实验和结论边界的账本 |
| Experiment Ledger | 保存实验环境、代码、数据、随机种子、指标和日志的账本 |
| Skill | 可复用的领域工作说明、约束和执行方法 |
| Tool | 可被 Agent 调用的原子、可验证能力 |
| Quality Gate | 决定某阶段产物能否进入下一阶段的自动化规则集合 |
| 全流程模式 | 从主题或任务约束开始，由系统推进到论文交付 |
| 半流程模式 | 用户提供部分研究产物，从指定阶段进入或接管流程 |
